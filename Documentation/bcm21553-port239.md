# BCM21553 Linux 2.6.39.4 port

This tree ports the Galaxy Y vendor kernel to upstream Linux 2.6.39.4. It
targets CM9/Android 4.0.4 on GT-S5360 (`totoro`), with builds for `cooperve`
and `tassve`, and a CM11 configuration variant. Hardware operation of this
port has not been tested. The earlier AOA hardware results describe 2.6.35.7.

## Source and branches

The upstream base is signed tag `v2.6.39.4`, commit
`ea0dc0dc1c1dca25e50384e300a528db57ee7de5`. The comparison base for reconstructing
vendor changes is signed tag `v2.6.35.7`, commit
`ea8a52f9f4bcc3420c38ae07f8378a2f18443970`.

The downstream inputs are `aoa/ics` at `b5646019` and `cm-11.0` at `4320a2c4`.
Both include the AOA backport. `port/2.6.39.4-common` holds shared code and ICS
defaults; `port/2.6.39.4-ics` derives from it. `port/2.6.39.4-cm-11.0` changes
the Bluetooth configuration to match the original CM11 branch. Original
branches and the original working checkout are retained.

`tools/port239/vendor-inventory.json` records each downstream addition,
modification and deletion, its destination and disposition. Newer upstream
implementations replace equivalent backports; device and Android changes are
adapted to the new core. Unrelated upstream board configurations are retained.

## Compatibility

The port keeps the vendor SDRAM base `0x81600000`, explicit decompressed kernel
address `0x81608000`, machine ID 477, reserved memory, NAND layout and YAFFS
format. It selects ARMv6K explicitly after the upstream CPU configuration split.

Broadcom IRQ handlers use `irq_data`. Legacy character ioctls use correctly
typed unlocked entry points, retaining allocator/job locking and wait paths.
YAFFS uses the newer mount/inode interfaces and an inode mutex for directory
seeking. Android wake locks, early suspend, Binder, ashmem, pmem, logging,
low-memory killing, VPN protocols and network accounting remain enabled.

The Broadcom USB controller and composite driver use the newer explicit bind
callbacks. The existing AOA ioctls, function ordering, USB identities and CM9
sysfs frontend remain. The old Bluetooth link-mode flushability option is
supported alongside the newer upstream socket interface. Native perf/OProfile
uses the same PMU IRQ 46 as the original vendor backend.

The ABI probe compares public ARM32 structure sizes, offsets and ioctl values
for pmem, ashmem, Binder, logger, AOA and V4L2 against the original source.
This is a static compatibility check, not a replacement for runtime testing.

## Build

Use the Android ARM EABI GCC 4.6 toolchain repository
<https://android.googlesource.com/platform/prebuilts/gcc/linux-x86/arm/arm-eabi-4.6>,
checked out at `d73a051b1fd1d98f5c2463354fb67898f0090bdb`, and host GCC 11.
The historical tag is `android-4.4.4_r2`; modern toolchain HEAD is unsuitable.

```sh
export CROSS_COMPILE=/path/to/arm-eabi-4.6/bin/arm-eabi-
HOSTCC=gcc-11 JOBS=6 tools/port239/build.sh /path/to/output totoro default
```

Select the ROM by checking out its port branch. Board choices are `totoro`,
`cooperve`, and `tassve`. The last argument is `default`, `on`, or `off` for AOA.
Defaults preserve the original configs: AOA enabled on totoro, disabled on the
other boards. The old `tools/aoa/build_kernel.sh OUTPUT [on|off]` interface
delegates to this builder for totoro.

The builder uses an external output directory, builds `zImage` and modules,
sets `LOCALVERSION=` explicitly, and checks the true `2.6.39.4` release and
module vermagic. `build-report.json` records source/config/kernel hashes and
module metadata. Stale `.ko` files outside `modules.order` are not deliverables.
MD4 is built in to preserve CIFS support without adding an external dependency;
totoro retains the original eight module filenames.

The config migration retains GRE through `NET_IPGRE_DEMUX`, the address-type
match through `NETFILTER_XT_MATCH_ADDRTYPE`, SNMP NAT through
`NF_CONNTRACK_SNMP`, and soft-lockup checking through `LOCKUP_DETECTOR`.
Removed internal symbols such as the BKL, old OProfile backend switches,
`PM_OPS`, and `INOTIFY` are replaced by their upstream implementations.

## Images and validation

Build validation covers three boards on each ROM branch plus totoro with AOA
disabled on each branch. The delivery report records exact revisions, logs,
warnings and checksums. Legacy compiler and section-mismatch warnings are
reported rather than suppressed.

Only the CM9/totoro output is repacked into a boot image. Repacking preserves
addresses, command line, second-image contents, cpio ownership/modes/links and
embedded recovery, retaining the known AOA init changes. Images must fit the
5,242,880-byte boot partition. CM11 receives a kernel and matching modules;
its own ROM ramdisk is required for a CM11 image.

Use the delivered CM9 bundle's installation and paired rollback instructions.
The boot image and all eight modules form one set. Existing 2.6.35.7 modules
cannot be reused with this kernel. Installation uses the phone's NAND-aware
`flash_image` utility, followed by readback verification; `boot_backup` is
preserved. This implementation does not flash or reboot any device.

Before declaring hardware support validated, check normal boot and recovery;
YAFFS and SD-card access; display, touch and keys; modem, calls and data; audio,
headset, camera and video codecs; Wi-Fi and Bluetooth; suspend/resume and
charging; ADB, mass storage, RNDIS and both AOA modes. Check kernel logs for new
faults and compare power behavior with the known working kernel. The earlier
AOA report's intermittent enumeration failure remains a known baseline issue.

Linux 2.6.39.4 reached end of life in August 2011. This port includes that
release and retained downstream fixes; it does not provide current security
coverage. New security backports are separate work. See the
[maintainer's release announcement](https://lwn.net/Articles/454028/).
